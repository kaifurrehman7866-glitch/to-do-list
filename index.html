    DOM ↔ Data Sync — Notes

    Every task lives first as a plain JavaScript object ({ id, text, completed }) inside a single tasks array — that array is the "source of truth," not the DOM. Any action (add, toggle, delete, filter) first mutates the array, then calls one render() function that clears #todo-list and rebuilds the visible <li> elements from whatever is currently in tasks, using document.createElement instead of building HTML strings. Because rendering always reads from the array rather than from whatever is already on screen, the DOM can never drift out of sync with the data — it's simply a fresh reflection of it after every change. The live counter and empty-state message are computed the same way, straight from the array length, so they update automatically every time render() runs.
